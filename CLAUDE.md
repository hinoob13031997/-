# Воронка умерших должников — вводная для новой сессии

Интерактивная схема воронки по умершим должникам: блоки, критерии отбора
и расчёт количества должников по загруженной выгрузке Excel.

- Сайт: https://hinoob13031997.github.io/-/
- Репозиторий публичный. ФИО, ИНН и прочие данные должников сюда не попадают.
  Исключение по решению пользователя (21.10.2026): общие данные (`data.bin`)
  открыто хранят внутренний ID, дату смерти и «Сумма долга + ГП Остаток»
  по каждому долгу — без этого у коллег не работают фильтры. Больше полей туда не добавлять.
- Есть вторая копия страницы как артефакт Claude (без общих настроек).

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | Вся страница одним файлом: разметка, стили, скрипт. |
| `config.json` | Общие настройки: критерии, тексты, свои блоки, положение блоков. Пишется со страницы. |
| `auth.json` | Токен GitHub, зашифрованный паролем (PBKDF2 + AES-GCM). |
| `rules-template.xlsx` | Шаблон для кнопки «Скачать таблицу правил»: листы, выпадающие списки, справочники. |
| `data.bin` | Общие данные: gzip JSON (ID, дата смерти, сумма, битсеты блоков). Пишется кнопкой «Опубликовать для всех». |
| `data-meta.json` | Метка версии общих данных; по ней страницы узнают об обновлении. |

## Как всё устроено

- **Данные.** Файл выгрузки читается в браузере и никуда не отправляется.
  Большие файлы (>25 МБ) читаются своим потоковым разбором zip, в память
  попадают только колонки, нужные для правил. Проверено на файле ~150 МБ.
- **Расчёт.** Правила отбора задаются только таблицей правил (xlsx).
  У блока: критерии (колонка, условие, значение), логика И/ИЛИ,
  «Брать из блока» (база вместо родителя) и «Вычесть блоки».
- **Тексты.** Название, формулировки критериев, открытые вопросы и примечания
  правятся на странице и при загрузке таблицы не затираются.
- **Блоки.** Добавляются кнопкой «Добавить блок» или строкой с новым кодом
  в таблице (столбцы «Родитель (код)» и «Тип блока»). Перетаскиваются мышью,
  положение сохраняется для всех. Кнопка «Вернуть блоки на места» сбрасывает.
- **Связи.** Ортогональный роутер: привязка к четырём сторонам блока,
  обход чужих блоков, предпочтение «низ родителя → верх потомка».
- **Общие настройки.** Пишутся в `config.json` через GitHub API под паролем.
  Чтение при недоступности API падает обратно на файл с самого сайта.

- **Общие данные.** Загрузивший нажимает «Опубликовать для всех» (нужен пароль правки):
  блоки считаются без фильтров по всем строкам, в `data.bin` уходят ID, дата смерти,
  сумма и состав каждого блока. У остальных страница раз в минуту проверяет
  `data-meta.json` через API с If-None-Match (ответы 304 не тратят лимит GitHub),
  при новой версии грузит `data.bin` и считает блоки как «состав блока ∩ фильтры» —
  это даёт ровно те же числа, что и расчёт по правилам. Свой открытый файл не
  подменяется: показывается подсказка и кнопка «Показать общие данные».
  Числа у смотрящих — по правилам на момент публикации.

- **Доступ.** Без пароля правки можно только смотреть, фильтровать и скачивать.
  «Загрузить Excel», «Загрузить таблицу правил», перетаскивание файла на страницу,
  публикация и правка критериев требуют входа (функция `needLogin`).

## Что уже умеет

Загрузка больших xlsx, фильтр по минимальной сумме «Сумма долга + ГП Остаток»,
переключатель «Смерть ≤ 5 мес.», выгрузка реестра по блоку и общего реестра,
проверка списка ID (в каком блоке каждый долг), скачивание и загрузка
таблицы правил, добавление/удаление/перемещение блоков.

## Открытые вопросы

1. **«Брать из блока» сбито.** У блоков «На рассмотрении в суде» и
   «Удовлетворено» в обеих ветках и «Отказ» в ветке взыскателя базой стоит
   «Судебный акт вынесен», а не своя ветка. Из-за этого дети больше
   родителей, а «На подаче» в ветке взыскателя считается почти ни от чего.
   Решить: вернуть базу на свои ветки или убрать вычитание.
2. **Ветка взыскателя почти пустая** из-за условий «есть имущество по
   обогащению» и «сумма по ИП > 100 000» на входе в ветку. Проверить,
   нужны ли они там.
3. **«Отказ» в двух ветках** отбирается по одному и тому же критерию.
4. **Пустые блоки без правил:** «Архив» в ветке взыскателя и низ ветки иска
   (без рассмотрения, отказ, удовлетворено, архив, обжалуем).
5. **Размер репозитория.** Каждая публикация добавляет в историю git несколько МБ.
   При ежедневных публикациях со временем стоит почистить историю `data.bin`.

## Как вести работу

- Правки страницы — в `index.html`, затем коммит и push в `main`;
  GitHub Pages обновляется за минуту-две.
- Перед коммитом проверять скрипт на синтаксис и прогонять страницу
  в headless-браузере на реальной выгрузке: цифры по блокам до и после
  правки должны совпадать.
- `config.json` правит пользователь со страницы. Трогать его только по
  прямой просьбе и всегда поверх последней версии из репозитория.
